## Task 1 — P0: Fix empty-prefix semantics in trie

**File:** `src/daf/cache/memory.py`

**Problem:** `_trie_insert` (line 121) adds each key to intermediate nodes but **not** to the root `_trie` node. As a result, `_trie_collect("")` returns `self._trie.keys` which is always empty. This silently breaks `delete_prefix("")` and `shake("")` — they no longer operate on the entire cache as the original linear implementation did.

**Fix:** Add the key to the root node's `keys` set at insertion time, and remove it from the root during deletion.

```python
# _trie_insert: add key to root before descending
def _trie_insert(self, key: str) -> None:
    self._trie.keys.add(key)          # <-- add
    node = self._trie
    for ch in key:
        node.children.setdefault(ch, _TrieNode())
        node = node.children[ch]
        node.keys.add(key)

# _trie_delete: remove key from root before descending
def _trie_delete(self, key: str) -> None:
    self._trie.keys.discard(key)      # <-- add
    node: _TrieNode | None = self._trie
    for ch in key:
        node = node.children.get(ch) if node is not None else None
        if node is None:
            return
        node.keys.discard(key)
```

## Task 2 — P1: Prune empty trie branches on delete

**File:** `src/daf/cache/memory.py`

**Problem:** `_trie_delete` removes keys from each node along the path but never removes child nodes that have become empty (no keys, no children). For a long-running process with high key churn, the trie accumulates dead structural paths — an unbounded memory-growth mechanism.

**Fix:** After walking the path and discarding the key, walk back up (or track the path) and remove child nodes that have `keys` empty AND `children` empty. The cleanest approach is a post-order pass using the tracked path.

```python
def _trie_delete(self, key: str) -> None:
    self._trie.keys.discard(key)
    path: list[tuple[_TrieNode, str]] = []
    node: _TrieNode | None = self._trie
    for ch in key:
        if node is None:
            return
        path.append((node, ch))
        node = node.children.get(ch)
        if node is None:
            return
        node.keys.discard(key)
    # Prune empty branches bottom-up
    for parent, ch in reversed(path):
        child = parent.children.get(ch)
        if child is not None and not child.keys and not child.children:
            del parent.children[ch]
```

**Tests to add in `tests/unit/test_components.py` (`TestMemoryCache`):**

```python
async def test_trie_prunes_empty_branches_after_delete(self) -> None:
    """After deleting all keys sharing a path, the trie collapses the
    branch rather than retaining structural garbage."""
    cache = MemoryCache()
    await cache.set("abcdef", "v1")
    await cache.set("abcghi", "v2")

    await cache.delete("abcdef")
    await cache.delete("abcghi")

    # Trie should be structurally empty — no residual child nodes
    # for 'a' or 'ab' or 'abc'
    removed = await cache.shake("abc")
    assert removed == 0

    # Re-insert a key that shares the same first character
    await cache.set("abcxyz", "v3")
    removed = await cache.shake("abc")
    assert removed == 1
```

## Task 3 — P1: Bound or remove `_namespace_cache`

**File:** `src/daf/core/access.py`

**Problem:** `self._namespace_cache: dict[str, str] = {}` (line 88) is an unbounded in-process cache of `resource_id → sha256` mappings. If `resource_id` values are attacker-controlled or come from an unbounded vocabulary, the dict grows without limit.

**Decision:** Remove `_namespace_cache` entirely.

Justification: SHA-256 of a short string (`resource_id.encode()`) is extremely cheap (sub-microsecond). The cached value saves negligible time compared to repository I/O, Pydantic validation, algorithm execution, and cache I/O. An unbounded dict is a worse trade-off than recomputing the hash.

**Fix:** Delete `self._namespace_cache: dict[str, str] = {}` from `__init__` and inline the computation in `_resource_namespace`:

```python
def _resource_namespace(self, resource_id: str) -> str:
    """Return a fixed-width namespace for a resource_id.

    Uses SHA-256 to produce a collision-resistant, structurally
    unambiguous prefix regardless of resource_id contents.
    """
    return hashlib.sha256(resource_id.encode()).hexdigest()
```

**Tests to update:** Remove `TestDataAccessNamespaceCache` from `tests/unit/test_components.py` (lines 419–462) — the cached-namespace behavior no longer exists. The remaining tests in `TestMemoryCache` and `TestMemoryRepository` already pass without namespace caching.

**Migration note:** `_namespace_cache` is a private attribute (`self._namespace_cache`). No external API changes. `DataAccess.get_components()` does not expose it.

## Task 4 — P2: Remove duplicate `graphify diagnose` invocation

**File:** `scripts/graphify_report.py`

**Problem:** Lines 33–41 run `graphify diagnose multigraph` twice. The first invocation (line 34–35) has `check=False` and its output is discarded. The second invocation (lines 37–41) captures stdout and does the real work. If the first invocation fails, it fails silently before the second invocation runs.

**Fix:** Remove lines 33–35 (the `run(... check=False)` call). Keep only the `subprocess.run(... capture_output=True)` block.

```python
# Remove this block entirely:
print("\n=== graphify diagnose multigraph ===")
run(["uv", "run", "python", "-m", "graphify", "diagnose", "multigraph",
     "--graph", str(GRAPH_JSON), "--json"], check=False)

# Keep only:
print("\n=== graphify diagnose multigraph ===")
result = subprocess.run(
    ["uv", "run", "python", "-m", "graphify", "diagnose", "multigraph",
     "--graph", str(GRAPH_JSON), "--json"],
    capture_output=True, text=True
)
DIAGNOSE_JSON.write_text(result.stdout)
```

## Task 5 — P2: Fail `graphify_affected.py` on subprocess error

**File:** `scripts/graphify_affected.py`

**Problem:** The `affected()` function (lines 47–53) calls `subprocess.run` without `check=True`. If `graphify affected` fails, the function returns empty stdout silently, and the caller prints "No impacted test files detected" — masking the real failure.

**Fix:** Add `check=True` to the `subprocess.run` call and wrap it to produce a useful error message:

```python
def affected(node_id: str, depth: int = 2) -> str:
    try:
        result = subprocess.run(
            ["uv", "run", "python", "-m", "graphify", "affected", node_id,
             "--depth", str(depth), "--graph", str(GRAPH_JSON)],
            capture_output=True, text=True, check=True,
        )
    except subprocess.CalledProcessError as exc:
        raise RuntimeError(
            f"graphify affected failed for node '{node_id}': "
            f"{exc.stderr.strip()}"
        ) from exc
    return result.stdout
```
