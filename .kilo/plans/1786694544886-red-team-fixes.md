# Red Team Fixes Implementation Plan

## Summary

Address all critical and high-severity findings from the red-team assessment. Core design principle: make security and correctness invariants explicit in the contracts, not implicit in usage.

---

## Design Decisions

### D1: Keep optional authorizer in core, require it in FastAPI adapter

`DataAccess` keeps `authorizer: Authorizer | None = None` for backward compatibility as a pure library. The security boundary is enforced at the FastAPI adapter: `DataAccessRouter` requires `get_current_user` and raises if missing. This makes the security invariant: *externally exposed routes cannot accidentally operate without an authorization policy*.

### D2: Remove `list_all()` from Repository protocol, add `create()`

`list_all()` leaks MemoryRepository assumptions into the generic contract. Replace it with `create(value: T) -> str`, which returns the generated resource ID. The repository owns identity generation (UUID, sequence, identity column, transactional allocation). This eliminates the TOCTOU race.

### D3: Implement filters and algorithm selection

Rather than removing public API fields, implement them properly since they are part of `QueryInfo`'s contract. Filters are applied in-memory against the retrieved resource. Algorithm selection uses `info.algorithm` to look up an algorithm from a registry. This is the safer path than a breaking API removal.

### D4: Cache key includes full query semantics

Cache key = canonical representation of all inputs that affect the result: `resource_id` + serialized `filters` + `algorithm` + `user_id`. This prevents cross-user leakage and cross-algorithm cache poisoning.

### D5: Per-resource cache invalidation

Replace `cache.clear()` with `cache.delete(query_key)` after mutations. This eliminates cache stampedes.

### D6: Preserve exception types, don't flatten to strings

Stop catching broad `Exception` in `DataAccess`. Expected errors (`NotFoundError`, `ValidationError`, `AuthorizationError`) return typed `QueryResult`/`MutationResult` with `error_type` preserved. Unexpected errors propagate as exceptions. At the FastAPI adapter boundary, catch `DataAccessError` subclasses and map to HTTP status codes. Never include raw `str(error)` in external responses.

### D7: Stop mutating private state in FastAPI adapter

Pass the authorizer through `DataAccessRouter.__init__` and construct `DataAccess` with it, or accept an already-authorized `DataAccess`. Do not assign to `self._daf._authorizer`.

## Implementation Tasks

### Phase 1: Security and correctness invariants (breaking changes)

1. **`src/daf/core/protocols.py`** — Update `Repository` protocol:
   - Remove `list_all()`
   - Add `create(self, value: T) -> str`

2. **`src/daf/core/access.py`** — Update `DataAccess`:
   - Replace `list_all()` + manual ID generation in `post()` with `await self._repository.create(info.data)`
   - Update cache key in `_execute_query()` to include `filters`, `algorithm`, and `user_id`
   - Apply `filters` to retrieved data before returning
   - Use `info.algorithm` to select algorithm (implement a simple registry or pass algorithm map)
   - Replace `cache.clear()` in `post()` with per-resource `cache.delete(query_key)`
   - Stop catching broad `Exception`; preserve error types in result envelopes

3. **`src/daf/core/factory.py`** — Update factory if needed to support new constructor args

4. **`src/daf/adapters/fastapi.py`** — Update `DataAccessRouter`:
   - Require `get_current_user` (raise `ValueError` if missing)
   - Stop mutating `self._daf._authorizer`; compose authorizer at construction time
   - Make `get_current_user` type `Callable[[Request], Awaitable[Any]]`
   - Sanitize error messages in HTTP responses (do not propagate `str(error)`)

5. **`src/daf/contracts/query.py`** — Add `error_type` to `QueryResult` and `MutationResult` if preserving types in envelopes; fix `datetime.utcnow()` to `datetime.now(timezone.utc)`

### Phase 2: Repository implementation updates

6. **`src/daf/repositories/memory.py`** — Update `MemoryRepository`:
   - Implement `create(value: T) -> str` using UUID or atomic counter
   - Remove or deprecate `list_all()`

### Phase 3: Tests

7. **Update existing tests** that rely on `list_all()` or no-authorizer FastAPI routes
8. **Add interaction tests** for:
   - Authorization × cache (same resource, different users get different cache entries)
   - Algorithm × cache (different algorithms produce different cache keys)
   - Filters × cache (different filters produce different cache keys)
   - Concurrency × POST (no ID collisions with new `create()`)
   - Cache key canonicalization
   - Error type preservation
   - FastAPI adapter requiring `get_current_user`

### Phase 4: Documentation

9. **Update `README.md`** — Reflect new Repository protocol, cache key semantics, and FastAPI adapter requirements
10. **Update `BUGS.md`** — Mark fixed issues
11. **Update `SECURITY.md`** — Reflect new security invariants
