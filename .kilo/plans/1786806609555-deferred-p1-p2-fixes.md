# Deferred P1/P2 Fixes for PR18

## Context

PR18 merged with two P1 inconsistencies and one P2 validation gap identified in adversarial review:
1. `GenerationKeyError` is defined, caught, but never raised — `_current_generation` silently falls back to `0`
2. `ResourceMemo` (used for generation locks) is unbounded despite PR docs claiming bounded lock striping
3. `graphify_affected.py` validates graph schema structure but not top-level JSON type

## Goal

Fix the three inconsistencies with minimal surface-area change, keeping the Python architecture frozen after this pass per the Rust migration strategy.

## Tasks

### 1. Fix `GenerationKeyError` to actually be raised

**File:** `src/daf/core/access.py`

- `_current_generation`: raise `GenerationKeyError` when cache value is `None` or not `int`
- `_advance_generation`: raise `GenerationKeyError` when cache value is present but not `int` (missing -> treat as 0 is acceptable for mutations)
- `_superedge_invalidate`: raise `GenerationKeyError` when cache value is present but not `int`

The existing `except GenerationKeyError` handlers in `_execute_query` and `_execute_cache_miss` will then become live code.

### 2. Bound `ResourceMemo` or correct the documentation

**Option A (recommended):** Add `max_size: int = 0` parameter to `ResourceMemo` with LRU eviction (consistent with `MemoryCache`). Configure `DataAccess` with a sensible bound (e.g., `max_size=256`).

**Option B:** Update `BUGS.md`, `CHANGELOG.md`, and `HANDOVER.md` to correctly state that `ResourceMemo` is unbounded and document this as deferred debt for the Rust migration.

Given the "freeze Python" directive, Option B is acceptable if we want minimal churn. Option A is better if we want the code to match the original T1 intent.

### 3. Validate JSON root type in graphify schema validator

**File:** `scripts/graphify_affected.py`

- `_validate_graph_schema` should check that `data` is a `dict` after `json.loads`
- Raise `RuntimeError` with clear message if root is not a dict (e.g., JSON array, string, number)

### 4. Update living docs

- `BUGS.md`: mark findings 36/37 as partially fixed or update descriptions
- `CHANGELOG.md`: add entries for the fixes
- `SESSION.md`: log the deferred-debt resolution
