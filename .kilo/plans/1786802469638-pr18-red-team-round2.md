## Design Decisions

### D1 — Lock Striping (Finding 1)

Replace unbounded `_generation_locks: dict[str, asyncio.Lock]` with a
fixed-size array of `N` locks.

```python
# In DataAccess.__init__:
self._generation_lock_count = 16  # internal, fixed
self._generation_locks: list[asyncio.Lock] = [
    asyncio.Lock() for _ in range(self._generation_lock_count)
]

# Replacement for _generation_lock():
def _generation_lock(self, resource_id: str) -> asyncio.Lock:
    namespace = self._resource_namespace(resource_id)
    idx = int(namespace, 16) % self._generation_lock_count
    return self._generation_locks[idx]
```

- Memory is bounded at O(N) where N = 16 (configurable internal constant).
- Two different resource IDs map to the same lock if they share the last
  hex digit of their SHA-256 namespace. This is acceptable: serialization
  is per-namespace-prefix-bucket, not per-resource.
- Remove `_generation_locks_lock` entirely; no dynamic allocation means
  no creation race.

**Rationale**: Fixed lock striping is the cleanest bounded-memory design
for the current single-process architecture. Weak references and
per-resource eviction are more complex and don't add safety here.

### D2 — Generation Key Missing = Error, Not Zero (Finding 2)

Change `_current_generation` to raise `GenerationKeyError` (subclass of
`CacheError`) when the `_daf_gen:<namespace>` key is absent.

```python
class GenerationKeyError(CacheError):
    """Raised when a required generation key is absent from the cache."""
    pass
```

Caller contract:

| Caller | Missing generation behavior |
|--------|-----------------------------|
| `_execute_query` (cache-hit path) | Treat as cache miss → call `_execute_cache_miss` |
| `_execute_cache_miss` (write path) | Initialize to 0; write cache entry with gen=0 |
| `_superedge_invalidate` | Read raw cache value directly; if missing/not-int → current=0 |

`_superedge_invalidate` currently reads the generation via direct
`self._cache.get(...)` (no `_current_generation` call), so it already
avoids the lock-doubling problem. After this change its behavior is
unchanged and remains correct.

**Rationale**: "Missing generation → generation 0" conflates two states:
never-initialized (legitimately 0) and evicted (unknown, must rebuild).
Treating eviction as "generation 0" can serve stale data when the LRU
evicts `_daf_gen:*` but leaves a query entry.

### D3 — Document Multi-Index Invariant (Finding 3)

Add an explicit atomicity note to `MemoryCache` class docstring:

```python
class MemoryCache:
    """In-memory cache implementation.

    ...

    Multi-index atomicity: mutation methods (``set``, ``delete``,
    ``delete_prefix``, ``shake``, ``clear``) must not ``await`` between
    updates to ``_cache``, ``_trie``, and ``_lru``. Introducing an
    ``await`` inside a mutation path can leave the three indexes
    temporarily inconsistent across Python task scheduling points.
    """
```

No code change required; this is a maintenance-hazard documentation
addition.

### D4 — Fix BFS Queue and Scope A*/BFS (Finding 4)

In `src/daf/utils/_recursion.py`:

```python
from collections import deque

def _bfs(self, root: Any) -> builtins.set[str]:
    result: builtins.set[str] = builtins.set()
    queue: deque = deque([root])
    while queue:
        current = queue.popleft()
        key = self._key_extractor(current)
        if key is not None:
            result.add(key)
        queue.extend(self._children_extractor(current))
    return result
```

In `src/daf/cache/memory.py`, add an experimental note to `_bfs_collect`
and `_astar_collect` docstrings:

```python
def _bfs_collect(self, ...):
    """Level-order terminal key collection.

    **Experimental** — no production consumer yet.
    """
    ...

def _astar_collect(self, ...):
    """Best-first terminal key collection returning keys with longest
    common prefix against ``target``.

    **Experimental** — no production consumer yet.
    """
    ...
```

**Rationale**: The reviewer is correct that algorithmic capability
accumulation without a consumer expands the trusted surface without
justification. Explicitly marking as experimental makes future removal
or promotion a deliberate decision.

### D5 — Fail-Closed Canonicalization (Finding 5)

In `scripts/graphify_affected.py`, `_canonical_node_id` should call
`_validate_graph_schema` when it reads graph JSON. If validation fails,
return `None` rather than falling back to `file_to_node_id`.

```python
def _canonical_node_id(graph_json: Path, path: str) -> str | None:
    if not graph_json.exists():
        return None
    try:
        raw = graph_json.read_text()
    except OSError:
        return None
    try:
        data = json.loads(raw)
    except json.JSONDecodeError:
        return None
    _validate_graph_schema(data)  # fail closed on malformed graph
    expected_id = file_to_node_id(path)
    if expected_id is None:
        return None
    matches = [n for n in data.get("nodes", []) if n.get("source_file") == path]
    if not matches:
        ...
    matches.sort(key=lambda n: n.get("id", ""))
    for node in matches:
        if node.get("id") == expected_id:
            return expected_id
    return matches[0].get("id")
```

