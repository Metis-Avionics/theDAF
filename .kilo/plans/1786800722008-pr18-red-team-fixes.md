## Must Fix (Merge Blockers)

### 1. CI checkout/base SHA mismatch

**Problem**: `.github/workflows/ci.yml` graphify job uses `actions/checkout@v4` with default `fetch-depth: 1`. The new `changed_files()` validates base SHA exists locally, causing deterministic CI failure.

**Fix**: Set `fetch-depth: 0` in the graphify job checkout step.

**Files**: `.github/workflows/ci.yml`

### 2. `_astar_collect()` algorithmic defect

**Problem**: Match score does not reset on mismatch. With keys `["xabc", "abc"]` and target `"abc"`, the path `x→a→b→c` scores `match_len=3` because after the root mismatch (`x` ≠ `a`), the algorithm increments when child `a` happens to match `target[0]`. The LCP of `"xabc"` with `"abc"` is 0, not 3.

**Root cause**: The heap entry stores `(priority, node, match_len)` but not the node depth. The algorithm uses `match_len` as both the LCP value and the index into `target`. After a mismatch at depth `d`, `match_len` stays `d-1`, but deeper nodes can still increment it because `target[match_len]` may match their own character.

**Fix**: Track depth in each heap entry. A child can only extend the match if the parent's `match_len == depth` (meaning no mismatch has occurred yet):

```python
heap: list[tuple[int, int, _TrieNode, int, int]] = [
    (0, 0, node, 0, 0)  # (priority, tiebreaker, node, depth, match_len)
]
counter = 0

for ch, child in current.children.items():
    child_depth = depth + 1
    if match_len < len(target) and match_len == depth and ch == target[match_len]:
        child_match = match_len + 1
    else:
        child_match = match_len
    counter += 1
    heapq.heappush(heap, (-child_match, counter, child, child_depth, child_match))
```

**Invariant preserved**: `match_len` at any node equals the LCP of the path-string to that node with `target`. Once a mismatch occurs (`match_len < depth`), all descendants share the same `match_len`.

**Files**: `src/daf/cache/memory.py`

### 3. Missing adversarial A* regression/property test

**Problem**: Existing test vectors don't contain `[mismatching prefix] + [target substring later]` structure.

**Fix**: Add two tests:
- **Regression**: `keys=["xabc", "abc", "xabd"], target="abc"` → `{"abc"}` (only exact prefix match)
- **Property-based**: Generate 200 random key sets and random targets; compare `_astar_collect(node, target)` against brute-force LCP model

**Files**: `tests/unit/test_components.py`

## Should Fix (Hardening Gaps)

### 4. Correct trie complexity documentation

**Problem**: Claims `O(prefix_length + K)` where K is matching entries. Actual cost is `O(prefix_length + subtree_nodes)` because DFS/BFS/A* visit every node in the subtree.

**Fix**: Update docstrings and CHANGELOG to `O(prefix_length + subtree_nodes)`.

**Files**: `src/daf/cache/memory.py`, `CHANGELOG.md`, `BUGS.md`

### 5. Make graph canonicalization deterministic

**Problem**: When multiple nodes share `source_file` and none matches hand-rolled ID, `matches[0]` depends on graphify output ordering.

**Fix**: Sort matching nodes by `id` before selecting first. Document preference order: (1) exact module-level match, (2) lexicographically first graph node ID.

**Files**: `scripts/graphify_affected.py`, `SECURITY.md`

### 6. Deepen graph schema validation

**Problem**: Current validation checks `isinstance(nodes, list)` and key presence, but not types, non-emptiness, or uniqueness.

**Fix**: Validate `node["id"]` and `node["source_file"]` are non-empty strings. Validate node IDs are unique.

**Files**: `scripts/graphify_affected.py`, `tests/unit/test_graphify.py`

### 7. Normalize `git diff` subprocess failures

**Problem**: `git rev-parse` failure raises `RuntimeError`, but `git diff` failure raises raw `CalledProcessError`.

**Fix**: Wrap `git diff` in try/except and raise `RuntimeError` with stderr context.

**Files**: `scripts/graphify_affected.py`

### 8. Remove duplicate graph extraction in CI

**Problem**: CI runs `graphify extract` then `graphify_report.py`, which runs `graphify extract` again.

**Fix**: Make CI invoke `graphify_report.py` as the single orchestrator.

**Files**: `.github/workflows/ci.yml`

### 9. Document LRU default as opt-in, not memory-safe

**Problem**: Security wording frames LRU eviction as a mitigation, but default `max_size=0` is unbounded.

**Fix**: Add explicit note in `README.md` and `SECURITY.md`: "`max_size=0` is backwards-compatible, not memory-safe. Set a positive bound for production deployments."

**Files**: `README.md`, `SECURITY.md`

### 10. Add missing adversarial test dimensions

**Problem**: Test corpus lacks several edge cases.

**Fix**: Add targeted tests in `tests/unit/test_components.py` and `tests/unit/test_graphify.py`:
- LRU: eviction of key that is prefix of another, eviction of near-duplicate keys, prefix delete followed by capacity pressure, set after prefix deletion
- Graphify: duplicate `source_file` nodes, invalid node types, empty node IDs, graph diff failure, affected subprocess failure, negative depth, malformed affected output

**Files**: `tests/unit/test_components.py`, `tests/unit/test_graphify.py`
